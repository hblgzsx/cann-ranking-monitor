# CANN Monitor

独立的 BatchedDiagGmmEm 比赛观察站，部署在 **https://hblgzsx.github.io/cann-ranking-monitor/**。不修改账号博客或其他系统，不使用自定义域名或全域 Service Worker。

## 功能

- 官方当前榜单、逐点历史最优组合榜、最佳单次历史提交榜，完整分页采集所有队伍。所有重算排名统一使用官方当前 TBest。
- 最佳单次历史提交：逐次按官方当前 TBest 计算本系统已采集的历史提交，取每队最高分的一次；每个测试点必须来自同一次提交，不拼接逐点最优。参考值变化后会重新选择最佳提交。
- 逐点明细包含 TBest 队伍。优先按官方 TBest 提交标识核对；公开接口未提供标识时，只展示已采集记录中原始耗时与官方 TBest 相同的队伍，并标注“历史耗时匹配”，不保证官方唯一归属。没有匹配记录时显示“未采集到归属”，不以当前最快队伍替代。
- 队伍详情：计算分 / 官方分 / 名次差异、趋势、逐点历史最好 / 最新 / TBest、得分与差距。
- 趋势图支持点击蓝色或灰色折线点查看该时刻的逐点组合分、官方分、分差和北京时间；可使用滑块、前后按钮、键盘左右键切换记录。时间相近的点可通过滑块逐一查看，手机端使用独立尺寸的图表与读数布局。
- 深浅主题（跟随首次系统偏好并记住手动选择）、搜索、关注、表头排序、CSV 导出、暂停刷新、详情分享链接。
- 官方当前榜单的每个 case 同时展示最新有效耗时与按官方当前 TBest 计算的逐点分（显示一位小数，未通过或缺失为 0）；总分和名次仍直接读取官方数据。
- 状态配色适配深浅主题：Pass 绿、Wrong Answer 红、Runtime Error 紫、Compile Error 橙、Time Limit Exceeded 琥珀、Memory Limit Exceeded 青、Output Limit Exceeded 粉、排队/评测中蓝，并始终保留状态文字。
- 点击“置顶队伍”可多选队伍，在同一张表的第 1 名前追加置顶行；完整榜单仍保留原记录和真实名次。置顶在三个榜单间共用，在当前浏览器持久保存，独立于搜索及仅关注筛选；CSV 只导出正常筛选结果，不重复置顶行。
- 历史由独立 `data` 分支持久化，所有访问者共享；网页每 15 秒检查数据。
- 采集目标间隔 15 秒。提供 Cloudflare Workers + D1 主采集器：云端保存变化与心跳，网页合并历史；GitHub Actions 作为备用采集与每 6 小时备份。启用情况以 `data-source.json` 和仓库变量为准；平台调度、网络或限流退避会延长实际间隔。

## 计分

`S_i = 100 / (1 + log(t_i / T_i) / log(1.5))`，总分为所有测试点得分的算术平均。

历史榜 `t_i` 取本系统观察到的该队每点有效最小耗时，`T_i` 使用当前官方 TBest。缺失点 0 分；只有该测试点状态为 Pass 的耗时参与历史最优，即使整次提交状态为 Wrong Answer / Runtime Error，已通过的点仍有效，与官方逐点计分一致。若官方参考回退，历史耗时优于当前 TBest 的点按 100 分显示并标注参考变化。底层使用 API 原始微秒值计算，页面仅作格式化。

**历史范围**：官方匿名榜单仅提供当前提交；全局历史接口要求登录。本系统不读取账号私有提交数据。历史从首次成功采集开始积累，不能恢复监控启动前或采集间隔中遗漏的提交；跨提交组合的分数不是官方最终成绩。旧快照可回填单次提交耗时向量，但不虚构未保存的提交 ID 或提交时间。`data` 分支保留原始快照历史提交，独立 `submissions` 数组持久保存所有已采集提交，趋势数组最多 2000 个变化点且不会裁剪提交记录。

## 本地运行

本地采集、网页及测试需要 Node.js 22+，无需运行时依赖。Cloudflare 部署使用开发依赖 Wrangler，运行 `npm ci` 安装。

```powershell
npm test
npm run collect
npm run serve
```

打开 `http://127.0.0.1:4173`。`collect` 默认更新 `data/latest.json`；设置 `OUTPUT_FILE` 可指定其他状态文件。

## 部署与采集

- `main`：站点源码，推送触发 `Deploy GitHub Pages`，只发布静态资源和最后一次有效快照，不发布脚本、临时文件或凭据。
- `data`：采集持久状态，根目录 `latest.json`。首次创建时从 main 建立分支并写入初始快照。
- 仓库 Settings → Pages 的 Build and deployment 使用 **GitHub Actions**。
- `Collect public ranking` 每 5 分钟定时启动，也可以手动运行；duration=0 只采一次，默认 4 分钟。备用轮次内目标每 15 秒写入一个快照；Cloudflare 启用后此任务跳过，避免双重采集。
- 定时任务使用 UTC `*/5 * * * *`；公开仓库标准 Linux runner。2026-12-05 12:45（北京时间，比赛结束后 1 小时）起定时采集自动跳过，手动采集仍可执行。也可以在 Actions 禁用此工作流。
- 采集只匿名 GET 官方公开接口，不需要任何账号、Cookie 或 Secret。GITHUB_TOKEN 仅由 Actions 用于本仓库 data 分支写入。Cloudflare 仅需 Worker + D1，不保存 GitHub 写入凭据。
- 数据异常、隐藏/封榜、分页变化或网络失败时保留最后有效快照，页面会显示过期。Actions 的定时任务不是严格实时服务，允许排队、丢失中间提交和短暂停顿。
- “读取最新快照”只立即检查后台已采集的数据，不会触发源站采集；没有更晚快照时明确提示“暂无更新的快照”。

公开来源：https://cannjudge.cn/public/2026_cann_final/batcheddiaggmmem/ranking

### 成绩分析工具
- 队伍对比：选择 2–4 队，按逐点组合、最佳单次或官方最新提交查看耗时、逐点分数和总分。
- 优化模拟：输入各点预计耗时，实时重算总分和预计名次；固定打开时的快照，不修改真实榜单。
- 历史提交对比：比较两份完整已采集提交的耗时、得分与变化，统一使用当前 TBest。
- 变动追踪：采集端比较前后快照，保留最近一次有意义的 TBest / 排名变动。排名旁显示该次升降；不表示全天累计。
- 刷新倒计时：展示下一次前端检查时间；前端读取快照，后台采集目标 15 秒，网络与 Actions 排队会延迟。

## Cloudflare 15 秒采集

完整部署、配额与备份恢复说明见 [cloudflare/README.md](cloudflare/README.md)。云端增量不会直接覆盖历史；每 6 小时备份到 GitHub，验证不可变备份后才归档已备份的 D1 事件。页面读取失败时保留最后有效数据，并显示采集或同步异常。15 秒轮询仍不能保证捕获两次采样间被覆盖的中间提交。

## 提交大屏与队伍战报

- `submissions.html`：独立大屏，按北京时间所选日期展示 ID 去重后的提交次数、活跃队伍、已知最终状态通过率、评测中 / 未知状态、近 15 分钟提交、24 小时分布、各队提交次数；小时和队伍可联动筛选。
- 下方完整已采集记录默认最新提交在前；支持关键词、队伍、状态、时间范围、记录身份、仅关注、日期、升降序、分页与筛选 CSV 导出，冻结列表不影响云端采集。点击提交可查看整次向量及当前 TBest 重算分。
- `team.html`：队伍战报，展示最佳单次分、逐点组合上限差距、提交活跃度、已知状态通过率、统一基准下的历史提交轨迹、按分数损失排序的薄弱点，以及与竞争队伍的逐点总分贡献。
- 大屏次数仅统计有 ID 和实际提交时间的记录；无 ID 或缺实际时间的旧快照不混入次数。时间缺失不以采集时间冒充。旧记录没有保存的状态、提交者显示未记录，官方分若可由当时快照核实则保留。相同 ID 的评测状态更新只更新原记录，不重复计次。

队伍战报支持按提交 ID 查看薄弱测试点，最佳单次/最新快捷切换、全部 case 展开、队内逐点提升与退化对比、固定提交分析链接。刷新时保留选定 ID；所有比较使用同一组当前 TBest，缺失点计 0 分。全站工具图标使用本地 SVG，兼容黑白主题。

TBest 变化页：官方基准变化曲线、逐点降幅/回退统计、带观察时间的变更明细、当前官方提交 ID 归属核对，以及固定历史提交在变更前后基准下的分数影响分析。全局 TBest 变更账本随云端备份保留；旧数据从队伍快照重建，不推测官方实际变更时间。
